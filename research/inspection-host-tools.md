# Source inspection: local-machine checks

Inspected October 23, 2026. Scope: source and selected test inspection, not execution or a security audit of these tools. Target workflow: a reported vulnerability leads to an evidence-backed assessment of this computer and its repositories, followed by remediation instructions.

## ai-agent-audit

Snapshot: `79c8536118facf7de9991dc0c13a4c317f0aa692`. Local clone: `research/upstream/ai-agent-audit`.

**Useful as a small collector/reporting reference; its vulnerability database is not a suitable general foundation.**

- **Explicit project discovery and scope.** Reads project locations from agent configuration, deduplicates roots, allows an explicit override, and records the roots checked. Borrow the idea of a scope manifest; implement Windows path handling separately. The root cap and search-depth/file caps must be exposed in coverage results. [Root discovery, common.sh:243–321](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/lib/common.sh#L243-L321), [run context, run-audit.sh:129–139](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/run-audit.sh#L129-L139).
- **Separate declared and resolved dependency evidence.** Module N checks package declarations, installed packages, and npm lockfile entries, including nested dependencies. This is useful for finding where a reported package occurs. However, the emitted resolved finding combines installed and locked states; our report should preserve those distinctions. [N_packages.sh:43–119](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/modules/N_packages.sh#L43-L119).
- **Structured findings with built-in redaction.** A common emitter produces module, severity, identifier, title, evidence, remediation, incident, and timestamp fields, applying secret redaction before writing. This is an implementable pattern for consistent collector output, though a pattern redactor is not a proof that all secrets are removed. [common.sh:83–99](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/lib/common.sh#L83-L99).
- **Actionable output.** The action-plan renderer preserves each finding's remedy and incident explanation. Reuse the finding-to-action relationship, adding an advisory source, exact target version or mitigation, and a verification check. [action_plan.sh:165–189](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/lib/action_plan.sh#L165-L189).
- **Focused fixture tests.** The tests create declared, installed, locked, and clean npm examples, plus similarly named packages, checking that the collector distinguishes these cases. These are useful test categories for a future collector. [test_detection.sh:10–19](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/tests/test_detection.sh#L10-L19), [assertions:72–77](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/tests/test_detection.sh#L72-L77).

**Do not carry over unchanged:**

- The IOC database is a short hard-coded list of package/version regexes and extension globs; the Python list is empty. This is a collection of specific incident checks, not a CVE/GHSA ingestion or version-range engine. Incident claims in that list were not independently validated in this inspection. [N_packages.sh:18–38](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/modules/N_packages.sh#L18-L38).
- Collection is bounded: npm search walks selected roots to depth four and takes only 200 manifest paths per root. Missing data cannot justify “not affected everywhere.” [N_packages.sh:118](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/modules/N_packages.sh#L118).
- The runner records a module in `MODULES_RUN` before completion; timeouts/nonzero exits produce warnings. A future implementation should persist per-check completion/error states, not equate “ran” with “finished successfully.” [run-audit.sh:150–177](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/run-audit.sh#L150-L177).
- The action-plan text assumes disappearance means the fix succeeded. That needs a stronger check: disappearance can also result from lost scope, a failed collector, or missing advisory data. [action_plan.sh:159](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/scripts/lib/action_plan.sh#L159).
- Its Bash/POSIX collectors target Linux/macOS. They do not provide native Windows inventory. [SKILL.md:1–5](https://github.com/bartek-filipiuk/ai-agent-audit/blob/79c8536118facf7de9991dc0c13a4c317f0aa692/SKILL.md#L1-L5).

## Wazuh

Snapshot: `dcb722fae3e85719eaaa006a45751c77819469e5`. Local clone: `research/upstream/wazuh`. This is development-branch source; these observations do not assert the same behavior in every stable release.

**Best host-inventory and matching reference among the seven, but too large to embed wholesale into a small skill collection.**

- **Windows application inventory across installation scopes.** The collector reads 32-bit and 64-bit machine uninstall registries, loaded user hives, Store packages, and discovered Python/Node installation paths. This is a useful checklist for a native Windows collector; one package-manager command would not cover the same scopes. [sysInfoWin.cpp:916–944](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/data_provider/src/sysInfoWin.cpp#L916-L944).
- **Windows build and patch evidence.** OS collection reads build number, update build revision (UBR), and display version. Hotfix collection queries both WMI and the Windows Update API. Keep OS build, patch inventory, and collector failures as separate evidence. [sysOsInfoWin.cpp:53–79](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/data_provider/src/osinfo/sysOsInfoWin.cpp#L53-L79), [display version:129–136](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/data_provider/src/osinfo/sysOsInfoWin.cpp#L129-L136), [sysInfoWin.cpp:1038–1065](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/data_provider/src/sysInfoWin.cpp#L1038-L1065).
- **Typed vulnerability applicability.** The candidate schema stores CVE, affected/unaffected/unknown status, platform/vendor restrictions, and inclusive/exclusive version boundaries. The scanner chooses comparison semantics by ecosystem rather than comparing arbitrary strings. [vulnerabilityCandidate.fbs:1–23](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/schemas/vulnerabilityCandidate.fbs#L1-L23), [packageScanner.hpp:58–69](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/packageScanner.hpp#L58-L69).
- **Platform and patch-aware matching.** The scanner accounts for Debian backport context; Windows OS matching can remove findings when an applicable hotfix is present. Borrow the principle that version alone is insufficient; use vendor advisories for the actual decision. [packageScanner.hpp:719–737](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/packageScanner.hpp#L719-L737), [osScanner.hpp:446–479](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/osScanner.hpp#L446-L479).
- **Preserve uncertainty when data is unavailable.** Package scanning flags an undecidable platform and marks packages unevaluated when no feed authority could answer, preserving existing findings. This is directly useful for the agent's “cannot determine” result. [packageScanner.hpp:630–644](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/packageScanner.hpp#L630-L644), [unevaluated handling:1343–1348](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/packageScanner.hpp#L1343-L1348).

**Limits and adaptation needs:**

- The Windows OS scan also discards a detection when remediation records are absent. Therefore, absence from Wazuh results is not sufficient evidence that a particular advisory does not apply. Surface missing-feed/missing-remediation cases explicitly in our agent instead. [osScanner.hpp:429–443](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/wazuh_modules/vulnerability_scanner/src/scanOrchestrator/factory/osScanner.hpp#L429-L443).
- The hotfix collector catches failures in its two API queries. A small collector for this project should return errors and collection coverage alongside patch IDs. [sysInfoWin.cpp:1047–1065](https://github.com/wazuh/wazuh/blob/dcb722fae3e85719eaaa006a45751c77819469e5/src/data_provider/src/sysInfoWin.cpp#L1047-L1065).
- These are inventory and advisory matching components. They do not, by themselves, establish that a vulnerable feature is enabled, reachable from an attacker, or used by a particular application's call path. That is an additional assessment step.
- Prefer an optional adapter to existing Wazuh inventory/results, or independently designed small collectors guided by the observed coverage. The dependency on feeds, databases, scan orchestration, and platform code makes copying the entire scanner unsuitable for a lightweight first version.
